# 故障恢复与循环性能：验证记录

- 将已确认的 `3001:[17] unable to cal ik` 从持久硬故障分离；等待新鲜静止反馈后返回 `ik_rejected`，保留使能。未知错误和真实故障保持保护行为。
- 分离伺服反馈、软件许可、控制模式、可接受动作状态；提供状态年龄、工作空间、速度、夹爪范围、工具参考点标识。
- 移除固定平移/旋转步长限制；workspace 越界返回可查询的拒绝原因，客户端补充越界轴、请求值和允许范围。
- 增加本地预检查、可选 SDK 端点 IK、动作查询、UUID 去重和发送前持久化记录。SDK 回执不明时监测实际运动，客户端通信超时后不自动重发。
- 常驻 ROS 客户端整合执行、动作后采集与状态关联；未知的上一动作阻止新提交。近期尝试反馈给 Codex，不设固定尝试次数上限。
- 图像采集复用动作完成边界之后的合格缓存帧，检查新鲜度、源时间差与到达时间差；关联机器人状态也不得早于动作完成边界。缺流和旧时间戳产生诊断，可重新采集。
- 保留完整三路图像，可按给定 ROI 导出 RGB 局部细节。
- 状态脚本减少 ROS 图遍历，动作反馈降频，增加分段耗时；PNG 低压缩保存，录像支持延后统一渲染。
- Skill 主文件精简为操作入口、接口与恢复规则；录像细节移入引用文档。

## 本地性能样本

三次查询的中位数：常驻客户端 **33.3 ms**，独立 `ros2 topic echo --once` **1113.2 ms**。一次模拟执行加动作后观察为 **0.416 s**。

这些数据来自 mock 机械臂和 64×48 合成图像，只证明本地 CLI 开销减少，不代表实机运动、真实分辨率相机或模型推理的加速倍数。原始样本见 `recovery_metrics.json`。

## 实机边界与部署

本轮没有连接、使能、运动或重启实机。ROS 接口已扩展，启用新版本时须协调更新依赖节点，不能混用旧消息定义；常驻客户端启动方法见 `../references/ros_workflow.md`。

- SDK 错误回调没有动作 ID，跨动作到达的延迟通知无法严格归属；序号隔离已处理的旧事件，但不能承诺消除所有迟到通知。实现不自动重复运动，实际状态始终优先。
- 工具号可读取，但轴尖/法兰/SDK 活动工具关系未经过本轮实机标定，明确标为未核实。
- `path_checked=false`：本地 workspace 与端点 IK 不证明整条路径、所持工具包络或桌面碰撞安全。未凭空添加场景几何或禁入区。
- SDK 查询仍串行；增加阻塞耗时诊断，没有在缺少线程安全证据的情况下改为并发调用。实际阻塞与控制器回调时序待实测。
- 实际相机时间戳必须与 ROS 时钟可比较。时间不匹配时返回诊断，不能用新到达的旧帧掩盖问题。
- 节点重启导致无法查询的未完成动作需核对控制器队列和真实状态；持久记录不会被自动删除以绕过这一检查。

## 后续实机就绪修复（2026-09-15）

已定位并修正启动时的两项适配问题：

1. Insight9 使用设备运行时间；camera.yaml 显式设置 `timestamp_mode=device`，原始时间保留，增加估算的主机关联时间。检测重复、回退、跳变和相对积压；恒定传输延迟未知，不宣称曝光时钟已硬同步。
2. 厂商 POSITION 模式允许 `state=1`，它不等于机械臂此刻发生位移。改为结合新鲜关节位置窗口和速度均值判断静止。现场静止速度单帧噪声可达约 0.0366 rad/s，逐帧 0.02 阈值会误拒绝；现在使用连续至少 250 ms 的位置变化及平均速度，明显速度、实际位移、过期数据和故障仍被拒绝。动作结束判定也使用同一静止逻辑。

构建、相关单元测试和 9 项模拟集成回归通过。已部署更新节点并使能；实机连续三次观察成功，`observation_valid=true`，单次观察约 0.12–0.14 秒。最终状态 `enabled=true`、`stationary=true`、`motion_allowed=true`、`fault=''`。原始验证见 `live_readiness.json`。本轮未发送 Cartesian、关节或夹爪运动目标；尚未进行实际 IK 拒绝后重规划的运动验收。
